# CrossPoint for C1 Max

Native MIPS/Linux reading app: a local EPUB/TXT/Markdown/Kindle/PDF text shelf and an OPDS 1.x browser for Calibre Content Server. This port follows the upstream CrossPoint Reader's OPDS interaction model; its ESP32/e-paper firmware is not flashed onto this Linux device.

## Online library

Open server settings with **S** on the shelf. Enter a full `https://server/opds` URL; leave both login fields blank for anonymous access. **O** opens the saved catalog. Settings live in `$C1_APPS_DATA/crosspoint/servers.json` with mode `0600`, outside application releases. Optional [private server defaults](../config/README.md) seed a fresh install and are deployed outside public releases; existing saved settings take priority. Existing additional server records are preserved; the current UI edits and opens the first server. Browsing child catalogs never overwrites the saved root address.

- Follow the server's newest/title/author/language/publisher/rating/series/tag categories, including nested directories.
- **W/S** or up/down selects an entry; **Enter** opens it. Touch a row to open it directly. The list scrolls through every entry, with six rows per screen.
- **A/D**, left/right, or the page buttons turn screen pages. At the end/start of a response, they follow the server's `next`/`previous` links. The footer shows the visible range within that server response. Back returns to the previous catalog and restores its selection. The Shelf button returns to local books.
- **F** or Search opens a physical-keyboard search field when the feed supplies a `{searchTerms}` template. Enter submits, top-right Backspace deletes, the middle Back key cancels. Calibre field queries such as `formats:EPUB` are passed through; no virtual keyboard is shown. OpenSearch-description discovery and OPDS 2 JSON feeds are not implemented.
- Selecting a book opens a format chooser, preferring EPUB. Supported acquisition types are EPUB, AZW3 (including Calibre's `application/x-mobi8-ebook`), MOBI, PDF, TXT and Markdown. A `/get/pdf/ID/library` URL is saved as `.pdf` based on its media type; it is never guessed to be EPUB simply because the URL lacks an extension.
- Loading and downloads run off the UI thread. The screen shows connection state, received/total bytes, average download speed and estimated remaining time; Back or Cancel interrupts the owned network process. Power exits the application and cancels its work.
- Downloads stream to disk, use a temporary file, check the format signature, then publish atomically. Existing books are preserved with a numbered suffix for duplicates. Partial/cancelled/failed transfers do not appear on the shelf. After completion the new book is selected; Enter reads it offline.

Feeds are capped at 1 MiB / 512 usable entries per response, with at most 16 download formats per entry and 32 navigation-history locations. Individual book downloads are capped at 128 MiB. Slow but progressing downloads may run for up to 30 minutes; a 12-second network read timeout still detects stalled connections, and cancellation remains available. Throughput depends on the server/network: these UI changes do not remove a remote bandwidth limit. These limits avoid loading an entire large library or book download into 128 MB RAM. No cover images are fetched. HTTPS certificate verification remains enabled; Basic-auth headers are only sent to the configured server origin, including across manual redirects. No automatic login, cookies, or netrc credentials are used.

## Local reading

Copy books into `/storage/apps/data/crosspoint/books`, or download them through OPDS. **R** rescans; **W/X** or up/down selects a local book, **A/D** scrolls the shelf, Enter reads. In the reader, A/D or left/right changes pages; EPUB additionally uses W/S (up/down) to change chapters and advances to the next chapter at the end of a page sequence. **Shift + Volume +/−** changes the body font by 2 pixels (14–32 px), preserves the current first character, and saves the size in `crosspoint/reader.json`. The header and controls keep their original size; the chord does not change audio volume. Back returns to the shelf, and Power returns to the launcher. The settings screen preserves physical-keyboard focus between all four fields; touch selects the field under the finger.

This is currently a **text reader**. EPUB text follows its spine; full CSS layout, book illustrations and cover rendering are not implemented. Kindle extraction uses libmobi and excludes DRM-protected books. PDF uses the bundled Xpdf `pdftotext`, so scanned/image-only PDFs and comics can download correctly but may have no readable text; OPDS format selection explicitly shows this limitation for PDF. EPUB reads the ZIP central directory once and inflates only the requested spine chapter in a cancellable worker. It validates member bounds and CRC, supports stored/deflated members, and skips `linear="no"` items. It no longer forks `unzip` for each chapter, parses large XML with regex, or imposes a 4 MiB whole-book EPUB text cap. Limits are 12,000 ZIP entries, 4 MiB central directory, 64 KiB container metadata, 2 MiB OPF/current chapter and 8 MiB compressed member; encrypted, split and ZIP64 archives are rejected. No chapter files are extracted to disk. TXT/Markdown/PDF extraction retains the 4 MiB text cap. The font file is mapped read-only and glyphs are cached to avoid repeated file seeks while measuring Chinese text. Reading pages now use the actual font metrics and 742×226 text viewport, preserving all UTF-8 text and paragraph breaks instead of cutting a fixed number of characters behind the screen edge. Layout is computed one page at a time and cached as you read, within the current chapter for EPUB. After changing font size, backward/forward pagination is also generated lazily around the current character instead of reflowing all preceding text. Non-EPUB total pages appear after reaching the end when paginating from the start. Book/chapter position is not persisted across closing the reader yet.

## Upstream references and licenses

Reviewed CrossPoint Reader commit [`0f01106ad6e9eacdd107a04b9128d15cd0ef02e6`](https://github.com/crosspoint-reader/crosspoint-reader/tree/0f01106ad6e9eacdd107a04b9128d15cd0ef02e6), especially `lib/OpdsParser/OpdsParser.cpp`, `src/activities/browser/OpdsBookBrowserActivity.cpp`, `src/util/OpdsFilename.cpp`, and `src/util/UrlUtils.cpp`: feed navigation, acquisition preference, search/pagination, parent history, bounded metadata and file naming. The Linux implementation uses TinyXML-2 instead of Arduino Print/Expat, and a cancellable wget transport instead of the ESP32 network stack. Relative references resolve against the current document using URI file/query semantics and inherited `xml:base`.

- TinyXML-2 **11.0.0** is vendored unmodified from [its official tag](https://github.com/leethomason/tinyxml2/tree/11.0.0); zlib license in `licenses/tinyxml2.txt`.

## Validation

`bash crosspoint/tests/run.sh` runs ASan/UBSan parser, malformed/truncated XML, namespace/entity, URI resolution, pagination/search, media-format and UTF-8 filename cases. Two optional arguments supply real root/acquisition feed fixtures for local QA; actual server catalogs and books are kept in ignored `.build` directories, never packaged.

`bash crosspoint/tests/run-transfer.sh` runs the Linux transport tests; `crosspoint/tests/transfer_test.py PATH_TO_TRANSFER_PROBE` starts two local HTTP fixtures. The Linux probe is built from `tests/transfer_probe.cpp`, `src/transfer.cpp`, `src/opds.cpp`, vendored TinyXML-2 and `shared/net.cpp` with pthread. It verifies redirects, same-origin Basic auth, cross-origin credential stripping, exact downloads, duplicate preservation, incomplete/HTML/oversized rejection and cancellation cleanup. This needs GNU wget and a C++17 compiler; device screenshot and deployment evidence is recorded in `../VALIDATION.md`.

`bash crosspoint/tests/run-epub.sh` runs ASan/UBSan tests against real stored/deflated ZIP fixtures: namespaced reading order, relative/percent-encoded paths, non-linear chapters, CRC and malformed/bounded entries, cancellation, and a 1,750-chapter book. Corrupting a later chapter does not block an intact earlier chapter. User books used for device performance checks remain in ignored QA directories.
