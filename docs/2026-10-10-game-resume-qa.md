# 2026-10-10：游戏息屏、NES 唤醒和操作提示

## 现场与判断

用户报告游戏中黑屏，短按电源可以继续同一局，之后出现无声和异常加速。初次读取时 NES 进程仍在、背光为 10，原厂 `sys.backlight.timer=1200000`、`sys.backlight.lock=0`，输入／音量辅助进程存活。随后 USB/ADB 消失，用户唤醒后电脑暂未重新枚举到设备。

目前没有取得这次 suspend/resume 的内核日志，不能把具体触发点写成已经真机复现。原厂 PowerManager 的本地反汇编确认背光和挂起分别消费 `sys.backlight.timer.reset`、`sys.suspend.timer.reset`；已有辅助程序只通知前者，且直接写 sysfs 点亮背光不等于恢复电源管理器状态。

NES 原代码只要 PCM 句柄非空就停止软件限速。声卡唤醒后若不再提供正常写入背压，会导致异常加速；不可恢复写入错误则永久关闭声音。两条路径均已修正。

## 改动

- Launcher 0.3.1 对 NES、PCSX4all、DOSBox 的前台子进程会话持有 vendor PowerLock 的 `suslock` 和 `bllock`。两项都收到 ACK 才算成功，每 5 秒检查；失败关闭整个连接并重试。退出时重置空闲计时并解锁，不改用户的计时和全局锁属性。Socket 不传给游戏，launcher 崩溃也会关闭连接。
- 共享活动通知同时重置背光和挂起计时。
- NES 0.2.2 每次 VBlank 都使用与 InfoNES CPU/APU 周期匹配的独立约 60 Hz 计时（避免直接取整 60 Hz 逐渐耗尽音频缓冲），声音可用与否都生效。BOOTTIME 检测超过 0.5 秒输出间隔并重建 PCM；其他输出错误每 2 秒重试，停止应用后不再重试。重开时继续读取系统音量，不解除用户静音。
- NES 默认左右边栏为实体按键提示。`T` 切换触摸按钮，并记住选择；实体提示模式不保留隐形触摸热点，切换只绘制边栏，不清空中间游戏画面。

## 已完成验证

- macOS ASan/UBSan 音频回归：音量、短写、错误恢复、重试间隔、休眠间隔重开、保留静音、显式停止后不重开、无声／声卡不阻塞时限速，以及正常阻塞不重复降速。
- Linux socket fixture：真实生产代码的 NUL/PID/ACK 协议、失败、重连、部分成功释放、重复释放与游戏范围；既有 PowerLock 超时／断线回归通过。
- MIPS 交叉编译完整应用通过；QEMU 执行 NES 音频与实际 CPU／APU／显示测试通过。边栏切换验证中间 framebuffer 像素未变化，隐藏触摸按钮不触发游戏动作。
- 使用实际 MIPS 渲染代码和打包字体生成边栏排版预览并检查。此图中间是黑色测试背景，不是运行游戏的真机截图，没有替换 README 真机截图。
