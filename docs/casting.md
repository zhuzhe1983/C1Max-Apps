# 无线投屏与输出模式

目前接入 StreamPlayer 视频／音乐、Bilibili、Airtune，以及需要 Mac 桥接的 NES、PCSX4all、DOSBox。它不是 launcher 全桌面镜像；其他应用不会因为选择了接收器就自动投屏。

## 选择接收器和输出方式

1. 词典和接收器连接同一局域网。Google TV 可用 Google Cast；其他电视可开启 AirScreen 等软件的 DLNA 接收。兼容性取决于接收器实际提供的服务。
2. 打开 **设置 → 无线投屏 → 搜索接收设备**，选择接收器。连接只建立控制会话，不会立刻开始媒体播放。
3. 在同一页面的 **各应用的输出方式** 中，分别选择 NES、PS1、DOSBox、StreamPlayer、Bilibili、Airtune 的模式。StreamPlayer 影片详情与 Bilibili 顶部也提供输出按钮；Bilibili 浏览时可按 T 切换。
4. 重新开始影片、曲目、电台或游戏。偏好按应用单独保存，默认 **仅本机**，修改不会打断正在播放的内容，也不会把其他应用改成同一模式。

| 模式 | C1 Max | 接收器 |
| --- | --- | --- |
| 仅本机 | 原有画面和声音 | 本应用不发送内容 |
| 仅远端 | 控制、状态或实体按键提示 | 内容画面与声音 |
| 本机＋远端（双屏） | 保留内容画面／媒体信息，本机不重复出声 | 内容画面与声音 |

双屏只有一个有声端，避免双扬声器回声。两块屏幕可以存在可见延迟，不是帧同步显示。各应用准备过程和断线处理不同，见下面的说明。

设置页可调节电视音量、暂停／继续和断开；实体音量键同步控制正在投屏的接收器，长按音量减三秒发送静音。接收器必须提供音量服务。网络完全失联时，词典无法保证远端缓存立刻静音。

## 视频、音乐与电台

| 应用 | 投送路径 | 本机与声音策略 |
| --- | --- | --- |
| StreamPlayer 视频 | Emby/Jellyfin 为接收器提供 H.264/AAC HLS，最高 1280×720、30 fps | 仅远端不启动本机解码；双屏另开低分辨率本机会话，本机静音 |
| Bilibili | C1 Max 受控转发当前 360p H.264/AAC MP4，补齐 CDN Referer | 仅远端不启动本机解码；双屏本机同时解码且静音 |
| StreamPlayer 音乐 | 接收器读取服务器的音频 URL | 仅远端／双屏在本机保留曲名、队列和控制，只由远端出声 |
| Airtune | 接收器读取电台公开音频 URL | 仅远端／双屏在本机保留电台列表和控制，只由远端出声 |

StreamPlayer 双屏使用两个独立服务器会话，会增加转码负载和网络流量。本机画面跟随远端进度，大于约 3 秒的偏移会尝试校正，但不能消除所有缓冲差异。Width/Fit 只改变本机视口与后续分段；本机字幕继续本地渲染，远端字幕由服务器烧录，切换远端字幕会重建其会话并短暂缓冲。细节见 [StreamPlayer](../streamplayer/README.md)。

Bilibili 的两个解码器独立取流，暂停／跳转作用于两端；本机旋转和裁剪不改变远端原始比例。本机先结束时保留最后一帧等待远端，不主动截掉远端尾部。转发不缓存整部视频、不需要 Mac 转码服务，但会增加 C1 Max 的网络转发负担。仍只支持单文件 360p MP4，不新增 DASH、弹幕或 B 站字幕。细节见 [Bilibili](../bilibili/README.md)。

StreamPlayer、Bilibili 和共享音频服务在没有接收器、远端加载失败或断开时提示错误并停止当前播放，**不会突然打开词典扬声器**。StreamPlayer 错误／控制页可按 L 或“切回本机播放”恢复本机输出；Bilibili 可切换顶部输出或按 T，然后重新播放；音乐／电台可在设置切为仅本机，再选曲目／电台。

音乐和 Airtune 的后台开关继续生效。曲名和媒体信息会发送给接收器；海报、文字排版取决于接收端，不是把词典整个收音机界面搬到电视。钢琴和其他本地合成音频未接入这套网络媒体投送，保持原有本机行为。

## 用 MacBook 接收

安装官方开源 [Kodi](https://kodi.tv/download/macos/)，在其 **Settings → Services → UPnP / DLNA** 中打开 **Enable UPnP support** 和 **Allow remote control via UPnP**。不需要分享本机媒体库。设备名称可自行设置，如 `C1Max MacBook`。Kodi 运行时词典即可搜索并选择；退出 Kodi 后停止接收。设置见 [Kodi 官方说明](https://kodi.wiki/view/Settings/Services/UPnP_DLNA)。

普通视频／电台只需 Kodi。下面的游戏画面另外需要 Mac 桥接服务，不要将两条路径混淆。

## 游戏：Mac 辅助编码

NES、PCSX4all、DOSBox 当前需要 Mac 同时运行 [游戏桥接服务](../tools/cast-receiver/README.md) 和 Kodi，并完成私有令牌配对。C1 Max 发送模拟器游戏区域的原始画面和声音，Mac 编码为 H.264/AAC HLS，Kodi 再读取。选择电视接收器本身不能代替这台 Mac；本版不是设备独立的 Google Cast／AirPlay 游戏镜像。

- NES／PS1 只发送有效游戏区域，接收端按 4:3 显示，不带两侧快捷键提示。
- DOSBox 4:3 填满传输画面，16:9 按正确比例上下留黑。
- 统一传输 **320×240、目标 20 fps、RGB565LE、44.1 kHz 双声道 PCM**。Mac 负责视频／音频编码，词典不调用曾导致重启的硬件编码驱动。
- 原始传输约 3.1 MB/s 视频加 176 KB/s PCM。较慢 Wi-Fi 会丢旧视频帧，避免积压和拖慢模拟器。PS1 高分辨率文字会缩小；仅远端也仍需完整模拟和采集，不能保证游戏帧率更高。
- 远端真正播放前保持本机画面和声音；成功后仅远端模式隐藏本机游戏画面、保留按键提示和状态，双屏保留两边画面，两种远端模式都只由远端出声。
- 接收端停止、桥接退出或网络故障后，游戏恢复本机输出并提示；短暂缓冲／暂停不自动恢复本机声音。完全失联的接收器仍可能短暂播放自己的缓存。

**Kodi／DLNA 的 HLS 有多秒缓冲，不适合依赖远端画面反应的动作游戏。** 双屏适合看本机操作、让旁人看远端。20 fps 只是采集目标，不是低延迟保证。Mac 桥接还可选择 `--preview` 打开本机低缓冲预览；它不是电视通用接收协议，也没有端到端延迟保证，勿与 Kodi 同时出声。

## 当前边界

- **全桌面／所有应用镜像、设备独立游戏编码未实现。** 硬件编码器探测期间曾发生重启，当前不继续调用该驱动，也不据此宣称编码性能足够。
- **AirPlay／Apple TV 未实现。** 目前只显示发现结果，没有完成配对、媒体投送或镜像。
- **Google Cast 需要实际接收器支持默认媒体接收应用。** 之前现场接收器返回过 `LAUNCH_ERROR / NOT_FOUND`，TLS／状态查询成功不等于媒体播放成功；可另选提供 DLNA 的设备。
- DLNA 的格式、HTTPS、HLS、跳转与字幕支持各异。Kodi 暂停时拒绝 Seek，发送端会在必要时短暂恢复、跳转，再保持暂停。
- 除 Bilibili 专用转发和游戏桥接外，媒体 URL 必须由接收端直接访问，包括服务器授权参数。没有供所有应用使用的任意 URL／文件代理。
- 局域网发现、控制与桥接当前使用 IPv4；VLAN、访客网络隔离、多播过滤和 Mac 防火墙可能影响发现或取流。

## 实现、隐私与验证

`shared/cast/` 是原生 C++ 服务，`shared/cast_client.cpp` 是本地 IPC 接口。网络工作在服务线程执行，界面不等待电视网络。单一媒体拥有者绑定 PID 与进程启动时间；旧应用不能停止另一个进程的新会话。应用退出或 launcher 会话结束时停止其远端内容；共享后台音频由音频服务继续持有。

本地 `data/cast` 目录为 0700，控制 socket、模式偏好和凭据文件为 0600。各应用模式存入独立的 `output-<app>` 文件。Cast 自签名证书按用户主动选择的设备进行首次信任指纹固定，证书变化需“忘记”后重连；此机制不等同于 Google 官方设备证书认证。正常 HTTPS 校验未关闭，未经选择不会自动连接接收器。

Bilibili 专用转发只接受当前已验证 CDN 的一段 MP4，使用每次播放新生成的 192 位随机 URL 令牌，并限制接收器 IP 和最多三个并发请求。支持 GET／HEAD／单区间 Range；拒绝重定向、请求体、多区间 Range 和任意 URL，不发送账号 Cookie。上游 HTTPS 验证证书，局域网向接收端使用 HTTP。临时地址／配置为 0600，停止时清理，不记录签名 CDN URL。

游戏配对信息与随机令牌保存在双方私有配置，源码不包含地址或凭据。游戏原始媒体及 HLS 为局域网明文，配对和会话令牌不是 TLS；不要将桥接端口映射到互联网。

设置的单独安装包自带 `c1max-castd`，完整运行时也提供共享副本。应同时更新设置、所需播放应用和 launcher 运行时，让模式选择、全局音量与退出清理使用配套版本。

可复现检查：

- `shared/cast/tests`：协议边界、本地 TLS 接收器、Linux IPC／SOAP、证书变化、进程退出与音量。
- `bilibili/tests/run-cast.sh`：真实 GNU wget／独立 HTTPS 测试源，覆盖 Referer、Range、证书拒绝、并发和清理；Player 使用可控接收状态验证三模式与控制。
- `shared/game_cast_tests/run.sh` 和 `tools/cast-receiver/tests/server_test.py`：游戏客户端接管／回退、RGB565、真实 FFmpeg H.264/AAC 编码、令牌、HTTP Range 与断开回收。

这些自动化检查不等于真实电视验收。`protocol-probe --exercise` 和 `c1max-bilibili-cast-probe` 会在人工选择的接收器实际播放；应单独记录接收器、模式、延迟和播放结果，不能把假接收器通过写成真机成功。

本轮真实设备结果及无隐私示例画面见[三输出模式 QA](2026-10-10-output-modes-qa.md)；其中明确区分完整播放验证、网络会话检查和仍未验证的内容。
