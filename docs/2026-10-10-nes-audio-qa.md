# NES 声音与音量修复（2026-10-10）

起点为 Apps `b71a54e`。本轮先遇到会话的网络、Git、ADB 和 Docker 限制；用户重启恢复权限后，主项目与 Apps 均成功 remote update，本地 main 与 origin/main 一致，再继续构建和真机验证。

## 原因与最终实现

- 旧五路混音在全零输入时仍输出 `-30720`，带来很大的直流偏置；直接写 tinyalsa 又没有应用系统 `softvolume`。新输出接收经过直流滤波的有符号 PCM，每次回调读取系统音量并缩放，约 5 ms 平滑变化。
- 第一版恢复声音后，用户反馈炮弹音色不对。继续发现旧 pAPU 的包络／扫频相位是无符号数却判断 `<0`，噪声移位序列与 NES 不同，波形的数值范围也不一致；简单相加无法得到正确声道比例。
- 最终接入固定 Game_Music_Emu 0.6.5 的 Nes_Snd_Emu / Blip_Buffer，只编译三个声音文件。InfoNES 的私有构建副本接入累计 CPU 时钟、`$4015` 状态和 `$4017` 帧计数器，移除旧 `$4015` 越界数组访问；不修改 `.deps` 原始源码。参考 [声音核心上游](https://github.com/libgme/game-music-emu/tree/9e23d10f9fd2a6a2f33b10912dd8dc7153258995/gme) 与 [NES 噪声硬件说明](https://www.nesdev.org/wiki/APU_Noise)。
- PCM 打开失败关闭错误句柄，短写逐段补齐，EINTR／欠载有限恢复；致命失败后静音继续。原声卡失败路径在每条扫描线等待约 16.7 ms，现改为每帧限速。

## 电脑与 MIPS 回归

- Clang ASan/UBSan：真实音频输出代码的有符号／静音样本、满幅不溢出、连续块、左右独立音量、运行中静音与恢复、5 ms 渐变、读控制失败、大块输入、短写、EINTR、欠载恢复／失败、零进展及句柄释放通过。
- 真实 Nes_Snd_Emu ASan/UBSan：NTSC 采样数、约 440 Hz 方波、噪声包络衰减、两种噪声模式、长度状态、帧 IRQ 的读取／清除、DMC 读取 ROM bank 通过。发现并处理了指令级时间戳在帧边界读取状态时的先后约束；没有关闭断言掩盖问题。
- MIPS/QEMU：上述输出和 APU 测试通过，真实 K6502 连续扫描线时钟、APU I/O 接口、VBlank 及 RGB555 黑白／主色转换测试通过。
- MIPS 完整应用构建通过，固定 InfoNES 的 mapper 45 原有编译警告仍存在，本轮未将它作为已修复项。键盘既有回归通过。

## 真机

- 从用户 NAS 的 FC《坦克大战》压缩包提取一份有效 iNES ROM（mapper 0，24,592 字节），拷入 `/storage/apps/data/nes/roms/Battle City.nes`。电脑／设备 SHA-256 一致；ROM 和 NAS 路径记录只保存在忽略目录，不进入 Git 或应用包。
- 设备实际接受 44.1 kHz、双声道 S16、1280×8 缓冲；1280×4 返回参数错误后正确回退。游戏画面和开场／关卡／开火能推进。
- 10.085 秒采样：约占单个 CPU 核心 33.32%，RSS 1244 KiB，硬件 PCM 指针平均约 44,040 帧/秒；短采样有计时误差，不等于逐帧视频 FPS 或所有游戏的性能。
- 额外链接只用于 QA 的 PCM 观察包装器，真实声卡仍播放，记录实际提交的样本统计。运行中音量 64→51→38→0，非零输出幅度随音量降低，零音量连续窗口的 peak/RMS/mean 均为零；未出现欠载恢复或写入失败。观察代码没有打包到正式应用。
- 用户已确认第一轮修复恢复声音，并指出炮弹音色差异；后续合成核心已替换并实测出声，最终主观音色尚未收到用户再次确认，不能声称和记忆中的红白机完全一致。

## 范围

仍是 InfoNES CPU／PPU，APU 接口按指令级总线时间工作，IRQ 在 CPU step 边界检查；没有模拟 DMC DMA 的 CPU 停顿，没有增加扩展声源／PAL。此次只验证用户提供的 mapper 0 游戏，不能推断全部 ROM 的兼容性。

完整证据位于忽略目录 `.build/nes-audio-20261010/`，包括编译、测试、PCM 统计、设备性能和截图；不包含麦克风录音。
