# Tox 聊天

C1 Max 的原生 LVGL 聊天客户端，直接链接 **c-toxcore 0.2.22**，接入现有 Tox 网络。无需浏览器、Qt 或 NAS 消息服务器。协议、密码学、节点发现和 NAT 穿透均由上游库处理；界面复用本项目的显示、触摸和实体键盘适配。

## 当前状态与真机截图

已交叉编译并安装到 C1 Max。2026-09-25 的电脑、MIPS 模拟执行和真机测试均通过两个专用测试身份的真实 Tox 收发；当天真机也曾连入公共 Tox 网络（观察到 TCP 通道）。当时空列表/两条记录画面的进程 RSS 约 3.7–3.8 MiB，不含 launcher 和系统；程序约 2.6 MiB。2026-10-02 复测了身份保存与损坏资料保护；最近一次启动仍显示“正在连接网络”，公共节点的当前可达性未确认。尚未完成手机/电脑实际客户端之间的长时间跨网聊天验收。

## 功能与操作

- 好友列表：W/S 选择，回车打开聊天；也可触摸好友。
- A 添加：输入完整 76 位 Tox ID，或点“扫码添加”／按实体拍摄键。识别后先核对 ID，再按回车发送好友请求。Shift + Q–P 输入数字。
- R 请求：W/S 选择请求，回车接受，退格拒绝；不会自动接受陌生人。
- I 我的 ID：显示本机 ID 和标准 `tox:` 二维码，方便手机或电脑客户端扫描；N 修改昵称。ID 同时导出到数据目录的 `my-id.txt`，便于通过 ADB 复制。
- 聊天：实体键盘直接输入，回车发送；右上退格键删除，中间返回键回到好友列表。双击 Shift 切换大小写。没有虚拟键盘；中文输入按拍摄键打开拼音编辑器，确认后填入草稿，再按回车发送。
- 触屏上下滑动查看当前六条消息；聊天标题右侧的 ↑/↓ 按钮可继续分段回看保存的记录，也支持方向键。
- 好友列表按退格，再回车确认，删除好友及其本机聊天记录。
- 电源键返回 launcher。右上角“后台：关／开”控制退出界面后是否保留收信服务，默认关闭。

当前支持文字、JPEG 照片和 WAV 语音附件，以及持久化待发送队列；不含群聊、实时音视频通话。最多 32 位好友、16 个待处理请求，每个好友最多保留 60 条消息；修剪旧记录时保留未完成的待发消息。单次输入最多 1024 UTF-8 字节。入队成功后清空输入框，保存失败时保留输入；尚未发送的输入草稿只保留在当前界面进程中。

“已发出”表示 toxcore 接受了发送；“已送达”表示收到对端客户端回执，**不是已读**。应用重启后未收到回执的旧消息显示“未确认”，不会自动重发。自动重连不会自动添加好友；仅投递用户已确认加入待发队列的内容。

## 0.3.0 离线待发送队列

- 好友离线也可发送文字、照片和录音。先把内容及发送状态原子保存到本机，再清空输入／退出预览；好友上线后，后台按每位好友的入队顺序发出消息或附件请求。照片与语音仍需对方接受。
- 聊天采用左侧浅灰、右侧浅绿气泡。黄色时钟表示待发送，灰勾表示 Tox 已接受发送，绿色圆勾表示收到对方送达回执（不是已读）；未确认／失败为警示图标，取消为灰色减号。队列列表使用同一套标识。
- 已接收／本机拍摄的照片直接显示缩略图，点击气泡放大，返回回到聊天。语音气泡显示时长与播放／停止按钮，点击即可试听，结束后自动恢复播放按钮；不自动播放收到的语音。缩略图按需解码、缓存有上限；无效或未下载完成的附件不会自动解码。
- **Shift + 音量＋向上滚动，Shift + 音量−向下滚动**，到达当前六条记录边缘时继续翻到前后记录。普通音量键仍调节音量。此快捷键需要本版本配套的基础音量服务；从较早的基础安装升级时，先通过 `tools/deploy.py` 更新基础安装，再使用逐应用更新。
- 聊天记录区分“待发送、已发出、已送达、未确认”；右上角“队列”可查看、取消待发项，或确认重发失败／未确认的项。取消后保留聊天记录，不再自动投递。
- 队列跟随本机身份保存在私有 `chat-<好友公钥>.json` 中，附件留在 `media/`。不会上传到服务器或 Git。应用更新、退出和重启不会清掉尚未发送的项；删除好友会删除此好友的待发队列。
- 每个好友最多 32 条未完成的发件项，全局最多 128 条。队列满或存储失败会提示，输入不被清空。旧聊天记录修剪不会删除待发项；记录损坏时保留文件并暂停该好友的发送。
- **退出界面后继续补发需要“后台：开”**。关闭后台后，队列仍保存，下次打开 Tox 才继续。重启设备后也需先打开一次 Tox；不强制唤醒设备或阻止休眠。
- 暂时离线／底层发送队列繁忙会自动等待，重试间隔最多 30 秒；上线后尽快继续。已交给网络但未收到回执的消息，在断线或服务重启后显示“未确认”，**不会盲目自动重发**。标准 Tox 文本没有跨重启的接收端去重 ID，无法保证网络投递与本地落盘恰好同时完成；用户确认重发时会提示对方可能已经收到。
- 新版队列不应由 0.2.x 客户端打开：旧版本不认识“待发送”状态，可能将其变成“未确认”。请使用 0.3.0 或更新版本处理队列。

## 0.2.0 拍照、语音与后台

- 聊天页点击“拍照”进入取景；空格／拍摄键拍照。取景右转 90°，输出 640×480 JPEG。拍好后再次确认才发送，返回可放弃。
- 点击“语音”开始录音；回车结束，最长 30 秒，16 kHz 单声道 PCM WAV。可先试听、重新录制，再确认发送。
- “附件”页显示传输进度、收到的请求与历史附件。W/S 选择，回车接受或查看；退格拒绝待接收附件／取消传输。图片可放大到独立查看页，语音需手动播放，不自动播放。
- 使用标准 Tox 文件传输，其他支持文件收发的客户端可将照片／语音作为 JPEG／WAV 文件接收。不是实时通话，也不要求对端安装 C1 Max 专用客户端。
- 单附件上限 4 MB，同时最多八项传输；接收前需要手动接受，附件目录上限 64 MB。尚未发出的附件会等好友上线后自动发出请求；已开始的传输因断线中断时标为失败，可在队列页手动重试。附件存于 `data/tox/media/`，不进入 Git 或更新包。
- 后台开关会保存。打开后，退出界面仍可收文字和附件请求；附件仍需返回界面接受。重新打开会连接同一后台服务，不创建另一份身份。
- 后台只运行网络、消息存储和待发队列，不持有 framebuffer、摄像头或录音设备。关闭开关后退出界面，服务在约三秒内结束。不会阻止系统休眠；设备休眠／断网期间无法实时收信。重启设备后需先打开一次 Tox，才开始常驻。
- 安装／卸载 Tox 时应用商店会结束其后台服务；个人数据保留，再打开时恢复。

## 二维码互加好友

![真机显示测试身份的 Tox 二维码](../docs/screenshots/tox-qr.png)

上图使用隔离测试身份，测试结束后已删除。用户已实际扫描专用测试二维码并添加成功；该测试身份不提供聊天服务。0.1.2 也已在固定设备、较小屏幕二维码的场景下成功识别并进入确认页。

- “我的 ID”使用标准 `tox:<76 位 ID>`，包含公开 ID，不包含私钥或聊天记录。
- 好友首页、我的 ID、添加好友页均可点击“扫码添加”，或按实体拍摄键。取景按设备方向顺时针旋转 90°。
- **0.1.2 高清扫码**：请求 1024×972 NV12，保留完整亮度图。1× 显示完整画面，1.5×／2× 显示中央裁剪；识别使用同一区域的真实像素，先快速识别，失败时尝试高清细节。属于数码裁剪，不是光学变焦。
- **Z** 循环倍率，或触摸 1×／1.5×／2×。切换倍率后重新对焦，请让完整二维码留在取景框内。
- 进入扫描后自动执行一次有界的对比度对焦；**F／实体拍摄键**重新对焦，**W／S**向两侧微调并停止当前自动扫焦。界面显示相对位置百分比，不表示距离或焦距。画面纹理不足时恢复起始位置，可对准二维码后重试。
- 摄像头 `/dev/video4` 和对焦节点 `/dev/v4l-subdev0` 由独立线程管理，不阻塞界面。返回、识别完成或退出应用时恢复扫描前的对焦位置并释放设备。不拍照、不写相册、不播放快门声。
- 对焦不可用时仍可扫码，界面显示状态。该板驱动报告0–4095，但实际把位置左移4位直接写入 DW9714；应用限制到芯片的10位位置范围0–1023，避免写入寄存器的模式位。只使用标准 V4L2 ioctl，不直接写 I2C 寄存器。
- 支持裸76位 ID与 `tox:` URI；检查十六进制、校验码和自己的公钥。扫描自己的 ID 会提示“这是自己的 ID，请扫描对方的二维码”。普通网址不会打开。
- 识别成功后仍需核对并按回车发送好友请求，不会自动添加。二维码边缘被裁掉时切回1×或增大距离；虚焦时先对焦，数码放大不能恢复已经模糊的细节。

![0.1.2 真机识别测试二维码后的确认页](../docs/screenshots/tox-qr-confirm.png)

电脑与 MIPS 测试覆盖原生细节裁剪、三档二维码识别、清晰度指标、对焦搜索边界和无纹理回退。实际识别率仍受屏幕反光、镜头距离、手抖、二维码大小影响；一次成功不等同于所有距离/光照均已验收。

## 身份与数据

所有用户数据位于 `$C1_APPS_DATA/tox`，默认 `/storage/apps/data/tox`，不进入应用包或 Git：

- `profile.tox`：私钥、身份、好友及核心保存状态。请备份；丢失后不能从昵称恢复原身份。
- `profile.tox.bak`：0.1.3 起保留上一次成功加载／保存的身份快照，包含私钥，同样需要保密。新身份第一次保存时备份与主文件相同。
- `chat-<好友公钥>.json`：本地纯文本聊天记录。
- `requests.json`：待处理好友请求。
- `my-id.txt`：自己的公开 ID，方便复制。
- `session.lock`：防止同一资料被两个本机进程同时打开。
- 可选 `bootstrap.json`：覆盖内置公共引导节点配置。

目录权限 0700，数据文件以 0600 原子替换保存，写入同步文件及父目录；本地文件没有另外设置口令加密。加载损坏的资料会持续显示错误并保留原文件，不会悄悄重建身份或自动回退备份。需要恢复时，先退出 Tox 并另外备份整个数据目录，再验证 `profile.tox.bak` 属于原身份后替换主文件。备份可能不含最近一次好友修改。正常应用更新保留整个数据目录。

## Tox 如何发现好友

1. Tox ID 包含长期身份公钥、防骚扰字段及校验，不包含固定 IP。
2. 首次启动通过若干已知 bootstrap 节点进入 DHT；保存状态里的节点信息也用于后续重连。
3. 客户端通过 Tox 的 onion 宣告/查找机制找到好友的可达信息，交换临时 DHT 公钥和可用中继，再由 DHT 查找与穿透流程建立连接。
4. 能直连时采用 UDP；无法直连时可通过 TCP relay 传递端到端加密的数据。引导节点不必承担后续聊天流量，中继转发密文。
5. 局域网发现用于找到本地 Tox 节点，不会把附近的人自动添加为好友。

所以 P2P 仍需要入网入口和协作节点，只是不要求一台集中保存账号、好友列表和聊天记录的服务器。若公网首次启动时所有引导节点都不可达，也没有可用缓存节点，就无法凭空发现网络。

内置 `bootstrap.json` 是从 [Tox 公共节点目录](https://nodes.tox.chat/json) 选取的七个数值 IPv4 节点快照，含公钥和 TCP 中继端口，优先尝试提供 443 端口的中继。使用数值 IP 避免静态 MIPS 程序的 DNS/NSS 依赖。每 30 秒在离线状态下重试；节点列表不从网络自动替换，可更新应用包或提供同格式的本地覆盖文件。节点在线状态和具体网络下的可达性不能保证。

参考：[官方协议（DHT / Onion / Friend connection）](https://toktok.ltd/spec.html)、[c-toxcore API](https://github.com/TokTok/c-toxcore/blob/v0.2.22/toxcore/tox.h)、[qTox / aTox 客户端](https://tox.chat/clients.html)。

## 构建与验证

运行仓库的 `tools/build.sh`，默认已包含 Tox，无需 `--local` 或私有配置。它使用固定的 toxcore commit 及其 cmp 子模块，关闭 toxav、上游测试和节点守护程序，链接 Debian bookworm 的目标架构静态 libsodium。无需在设备上安装包管理器或动态库。构建会生成 Tox 0.3.0 清单、launcher 入口及透明图标。

电脑端回环互通与离屏界面：

```sh
docker run --rm -v "$PWD:/work" c1max-apps-builder:bookworm sh -ec '
  cmake -S tests/tox -B .build/tox-tests -DCMAKE_BUILD_TYPE=Debug
  cmake --build .build/tox-tests -j4
  mkdir -p .build/tox-tests/data
  .build/tox-tests/tox-roundtrip .build/tox-tests/data
  .build/tox-tests/tox-qr .build/tox-tests/data/qr
  .build/tox-tests/tox-scan-test .build/tox-tests/data/qr.id
'
```

二维码测试用 toxcore 生成地址，验证 URI/校验码/自身 ID 拒绝，以及真实二维码解码、四方向旋转、相机亮度范围、带行填充的帧和镜像；`tox-scan-test` 读取前一步生成的测试 ID，验证三档裁剪与对焦搜索。二维码测试程序不会发送好友请求。

测试创建两个专用身份，禁用公共引导和局域网发现，只通过 `127.0.0.1` 相互引导。验证人工接受好友、中英文双向收发、送达回执、离线失败、输入长度、身份互斥锁、重启保留资料、备份恢复原身份与好友、全零损坏资料保护，不联系真实用户。测试生成的身份位于被忽略的 `.build/`，不应上传。

离屏预览程序 `tox-preview` 只用于测试，不进入设备包；按键脚本和 PPM 输出路径分别通过 `C1_TOX_QA_KEYS` / `C1_TOX_QA_OUTPUT` 指定。主应用本身没有模拟聊天或伪造在线状态的代码。
